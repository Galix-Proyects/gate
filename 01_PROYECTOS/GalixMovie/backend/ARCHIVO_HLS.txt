2.1. FLUJO DE SOLICITUD (Roku solicita un episodio)

  PASO 1: Roku descarga playlist:
    GET /GalixMovie/backend/stream.php?hls=1&path=HLS_TEST/S02E03/playlist.m3u8
    → Nginx → php-fpm → stream.php → rclone → GDrive
    → Devuelve playlist con URLs RELATIVOS para cada segmento

  PASO 2: Roku parsea playlist y descarga segmentos:
    GET /GalixMovie/backend/stream.php?file=HLS_TEST/S02E03/playlist000.ts
    → Nginx → php-fpm → stream.php → rclone → GDrive
    (se repite para cada segmento, paralelamente)

  PASO 3: Roku reproduce segmentos HLS secuencialmente

2.2. FORMATO DEL PLAYLIST (ejemplo)

    #EXTM3U
    #EXT-X-VERSION:3
    #EXT-X-TARGETDURATION:19
    #EXT-X-MEDIA-SEQUENCE:0
    #EXT-X-PLAYLIST-TYPE:VOD
    #EXTINF:16.099000,
    stream.php?file=HLS_TEST/S02E03/playlist000.ts
    #EXTINF:5.672000,
    stream.php?file=HLS_TEST/S02E03/playlist001.ts
    ...
    #EXT-X-ENDLIST

  NOTA: Los segmentos usan URLs RELATIVOS (stream.php?file=...) para que el Roku
  los resuelva contra la base del playlist URL. NO usar rutas absolutas (/gdrive/...)
  porque el VideoNode de Roku no las resuelve correctamente en HLS.

2.3. CONTEO Y TAMAÑO DE SEGMENTOS

  - ~370-400 segmentos por episodio (variable según duración real)
  - Cada segmento ~10s de video
  - Tamaño: 640KB-3.2MB (VBR, variable según complejidad de escena)
  - Bitrate promedio estimado: ~800kbps - 1.4Mbps
  - Codec: H.264 en contenedor MPEG-TS (.ts)
  - Content-Type: video/mp2t

 3. stream.php — SISTEMA DE CACHÉ DE PLAYLISTS
╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌

3.1. UBICACIÓN CACHÉ

  Directorio: /Users/israeltorres/hls_temp/{directorio_episodio}/
  Ejemplo:    /Users/israeltorres/hls_temp/S02E03/playlist.m3u8
  TTL:        60 segundos

3.2. ALGORITMO (stale-while-revalidate)

  1. ¿Cache existe?
     → SÍ: ¿Edad <= TTL? → SERVIR CACHE (fresh)
     → SÍ: ¿Edad > TTL?  → SERVIR CACHE (stale) + regenerar en background*
     → NO: Fetch de rclone → aplicar reescrituras → guardar cache → servir

  2. *Regeneración en background:
     - Ocurre DESPUÉS de enviar la respuesta HTTP (fastcgi_finish_request)
     - curl a rclone con timeout 30s
     - Reescribe URLs de segmentos (playlist###.ts → stream.php?file=...)
     - Agrega #EXT-X-PLAYLIST-TYPE:VOD
     - Guarda en archivo de cache
     - exit (termina el proceso hijo)

3.3. REWRITES QUE APLICA stream.php AL PLAYLIST CRUDO

  a) Segmentos .ts:
     RAW:    playlist000.ts
     REWRITE: stream.php?file=HLS_TEST/S02E03/playlist000.ts
     (usa regex: /^(playlist\d+\.ts)$/m )

  b) Tipo de playlist:
     Agrega: #EXT-X-PLAYLIST-TYPE:VOD (después de MEDIA-SEQUENCE)

3.4. SEGURIDAD

  El parámetro ?file=... solo acepta rutas que empiecen con "HLS_TEST/"
  (strpos(, "HLS_TEST/") !== 0 → 403 Forbidden)

8.1. FLUJO DE REPRODUCCIÓN (MainScene.brs)

  playFromGrid(node):
    1. Guarda wasPrebuffering = m.prebufferActive
    2. m.prebufferActive = false
    3. Obtiene URL del video
    4. Configura VideoNode (tamaño, posición, visibilidad, mute)
    5. Inicia intro animada (timer, spinner)
    6. Decide: ¿reutilizar buffer existente?
       - SÍ (alreadyHasContent): solo llama control = "play"
       - NO: content = invalid → crea ContentNode → content = vc → control = "play"
    7. setFocus(true)

  onVideoStateChange():
    - playing/buffering/error → suppressCloseVideoPlayer = false
    - paused → showOverlay
    - playing → (si prebuffer, pausa; si no, setFocus)
    - buffering → visible = false (si prebuffer)
    - error → marca prebufferFailedNode
    - finished/stopped/error → si suppress/prebufferActive, return
      → si episodio: reabre modal detalles
      → si no: closeVideoPlayer()

  playFromDetails(node):
    - Similar a playFromGrid pero sin prebuffer ni intro
    - Siempre crea contenido fresco
    - Cierra overlay, reproduce directamente

8.2. PREBUFFER (prebufferEpisode)
    - Se ejecuta en segundo plano (al navegar entre episodios)
    - Crea ContentNode y llama control = "prebuffer"
    - Cuando completa (state = playing), pausa inmediatamente
    - El contenido queda en RAM para reproducción instantánea

8.3. FLAGS CRÍTICOS

  m.suppressCloseVideoPlayer (bool):
    - TRUE: el handler de stopped/finished/error NO procesa el evento
    - FALSE: procesa (reabre modal o cierra player)
    - Se activa en playFromGrid y se desactiva al llegar a playing/buffering

  m.prebufferActive (bool):
    - TRUE: modo precarga activo (no mostrar video, pausar al completar)
    - FALSE: modo reproducción normal
    - Se limpia en onVideoStateChange (cuando prebuffer completa)
    - Se limpia en playFromGrid (al iniciar reproducción manual)

  m.prebufferedNode, m.prebufferContentNode:
    - Referencias al nodo y ContentNode del último prebuffer
    - Se usan en alreadyHasContent para decidir si reutilizar

8.4. HITOS DE REPRODUCCIÓN Y TIEMPOS ESPERADOS

  Tiempo hasta playing (prebuffer existente):   0.9-1.4s
  Tiempo hasta playing (buffer fresco):         2-3s (depende de rclone)
  Segmentos prebuffer:                          10 (~100s de contenido)
  Timeout prebuffer por segmento:              15s
